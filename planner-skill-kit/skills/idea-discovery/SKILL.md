# idea-discovery — 사업 아이디어 발굴·정의·검증 통합 스킬 (v2)

> **한 줄 정의**: 1인 창업가의 *흐릿한 아이디어*를 *발굴 → 아이템명 → 검증* 3단계로 순차 정제해, 사업 추진의 *Go/No-Go 1차 판단*까지 30분 안에 끝내주는 스킬

> **v2 핵심 변경 (2026-05-16)**:
> - 정책·트렌드 경로에서 **발화 시점 웹 리서치 의무화** (학습 데이터 한계 보완)
> - references 다중 소스 카테고리 균형 (단일 출처 의존 금지)
> - 모든 정책·트렌드 인용 시 **출처 URL 동반 강제**

---

## 1. 언제 호출되나

### Description 매칭 키워드
- *아이디어 발굴*, *사업 아이템*, *창업 아이템*, *아이템명*
- *아이디어 검증*, *시장성 평가*, *약점 분석*
- *이키가이*, *SCAMPER*, *6 thinking hats*, *정책 기반*, *트렌드 기반*
- *예비창업*, *초기창업*, *K-스타트업* (정책 경로 트리거)

### 사용 시나리오 3가지
1. **사업 아이디어가 한 줄로 정리 안 됨** — 4가지 발굴 경로 중 본인 유형에 맞는 1~2개로 후보 5개 도출
2. **후보 2~5개 중 결정 못 함** — 아이템명 작성 단계의 8개 후보 + TOP 3 + 강화 옵션 5개로 정제
3. **아이디어 검증 안 됨** — 시장·기술·운영 3축 진단으로 추진/폐기 판단 + 정부지원 신청서 *추진 배경* 섹션 자동 인용

## 2. 입력 (Input)

### 필수 입력
- `agents/strategy-team/memory/context.md` — 대표(나)의 핵심가치·미션·절대 안 하는 것

### 선택 입력
- 기존 사업 아이템 (있으면 SCAMPER 경로 진입)
- 본인 잠재·자원·관심사 메모 (있으면 이키가이 시작점)
- 정부 정책 자료 — 정책 경로 시 references + **발화 시점 웹서치** 결과 교차 인용 (이재명정부 123대 국정과제 + 최신 사업공고)
- 트렌드 자료 — 트렌드 경로 시 references + **발화 시점 웹서치** 결과 교차 인용 (트렌드 코리아 + 삼정KPMG + 와이즈앱 + 모비인사이드 등 다중 소스)

### 메모리 의존성
- 작업 직후 `agents/strategy-team/memory/decisions.md`에 *최종 아이템명 + 검증 결론* 자동 기록
- `agents/strategy-team/memory/glossary.md`에 *발굴 경로별 핵심 용어* (이키가이 4요소, SCAMPER 7원칙 등) 자동 추가

## 3. 처리 흐름 (Process) — 3단계 순차

### 0. 사전 자가진단 (2분)
다음 *2개 이상* 해당하면 본 스킬 사용 권장:
- [ ] 사업 아이디어를 *한 줄로* 명확히 적기 어렵다
- [ ] 후보 아이템 2~5개 중 *어느 것이 본격 추진감인지* 결정 못 한다
- [ ] 본인 아이디어가 *시장에서 통할지* 검증한 적 없다
- [ ] 본인 *강점·자원·관심사*와 아이디어의 적합도 모른다
- [ ] 정부지원·투자유치를 노리지만 *추진 배경*을 어떻게 쓸지 모른다

### 0-1. ⭐ 발화 시점 웹 리서치 의무 (정책·트렌드 경로 진입 시 필수)

**학습 데이터의 한계 보완을 위해, 다음 경로 선택 시 반드시 웹 리서치 선행:**

| 선택 경로 | 필수 웹서치 키워드 |
|---|---|
| ① 정책 기반 | "[현재 연도] 중기부 창업지원 통합공고", "이재명정부 국정과제 [도메인]", "[현재 연도] TIPS OR 모태펀드" |
| ② 트렌드 기반 | "[현재 연도] 한국 소비 트렌드", "[현재 연도] 한국 산업 트렌드 KPMG OR 삼정 OR PwC", "[현재 연도] 1인 창업 트렌드" |

**출력 시 인용 규칙**:
- 모든 정책·트렌드 인용은 **출처 URL 동반 필수**
- "트렌드 코리아 2026"이나 "이재명 국정과제" 단일 인용 **금지** — 최소 3개 출처 교차
- 학습 데이터로만 답변 시 *반드시 명시*: "(주의: 학습 데이터 기준이며 [날짜] 이후 변경 가능)"

자세한 웹서치 절차·키워드 풀은 `references/discovery_policy.md`(§ 과업 0)·`references/discovery_trend.md`(§ 과업 0) 참조.

### 0-2. ⭐ Step 1 — 메모리 3종 자동 생성 (필수 · 건너뛰지 말 것)

> ⚠️ **Claude(스킬)에게 — 본 단계는 §1 발굴 진행 전에 *반드시 직접 수행*. 사용자에게 묻거나 안내 텍스트만 출력하지 말 것. Filesystem 도구(Read·Write·LS·Bash)를 직접 호출해 *실제 파일을 작성*하라.**

#### Step 1-A. 작업 폴더 경로 확보
1. 사용자에게 *한 번*만 작업 폴더 경로 물음: *"본인 사업 작업 폴더 경로를 알려주세요. 예: `F:\ClaudeCowork\notefriends\`"*
2. 응답 받으면 *경로 변수 `$BIZ`*로 저장
3. 폴더명에 한글·공백·대문자 발견 → 경고 1줄: *"영문 소문자 + 언더스코어 권장"*

#### Step 1-B. 메모리 3종 파일 존재 여부 직접 확인
LS 도구 또는 Bash `ls` 도구로 다음 3개 파일이 *실제로 있는지* 확인:
- `$BIZ\agents\strategy-team\memory\context.md`
- `$BIZ\agents\strategy-team\memory\decisions.md`
- `$BIZ\agents\strategy-team\memory\glossary.md`

#### Step 1-C. 없으면 직접 생성 (Write 도구 호출)
3종 중 하나라도 없으면 *아래 인라인 템플릿*을 Write 도구로 *그대로 작성*하라. plugin cache 경로 의존 금지(시스템마다 다름) — 아래 인라인 백업 사용:

**`context.md` (CEO가 채울 5섹션 + IKIGAI 4축 빈 양식)**:
```markdown

> 본 파일은 회사의 정체성을 담는 가장 중요한 메모리입니다.
> 모든 5개 스킬이 작업 전 본 파일을 먼저 읽습니다.

## 1. 사업 한 줄 정의
(예: 우리는 [고객]의 [문제]를 [솔루션]으로 해결한다)

[여기 작성]

## 2. 미션 (한 줄)
> 우리가 세상에 어떤 기여를 하려 하는가

[여기 작성]

## 3. 비전 (한 줄)
> 5년 후 우리는 어떤 모습일까

[여기 작성]

## 4. 핵심 가치 3가지
1.
2.
3.

## 5. 절대 안 하는 것 (Won't) 3~10가지
1.
2.
3.

## 6. IKIGAI 4축 (선택 — 1일차 시연 시 활용)
- 좋아하는 것 (LOVE):
- 잘하는 것 (GOOD AT):
- 세상이 필요로 함 (NEEDS):
- 돈 받을 수 있는 것 (PAID FOR):
```

**`decisions.md` (스킬이 자동 누적, 빈 채로 시작)**:

**`glossary.md` (스킬이 자동 누적, 빈 채로 시작)**:

(아직 용어 없음. 첫 스킬 호출 후 자동 채워집니다.)

3개 파일 *직접 작성* 완료 후, 다음 메시지 중 하나 출력:

### 1. 발굴 (Discovery) — 4가지 경로 2×2 매트릭스

> ⚠️ **본 단계 진입 전 Step 1(§0-2) 반드시 완료**. context.md가 비어 있으면 발굴 진행 금지 — 일반론 결과만 나옴.

|  | **외부 환경에서 출발** | **내부에서 출발** |
|---|---|---|
| **새 아이디어 도출** | ① 정책 기반 / ② 트렌드 기반 | ④ 이키가이 |
| **기존 아이디어 강화** | — | ③ SCAMPER |

사용자 유형별 자동 추천:

| 사용자 유형 | 추천 경로 | references 파일 |
|---|---|---|
| 정부지원·공공 지향 | ① **정책 기반** (123대 국정과제) | `discovery_policy.md` |
| 시장 흐름 타고 싶음 | ② **트렌드 기반** (트렌드코리아×AI) | `discovery_trend.md` |
| 기존 아이템 있고 강화 필요 | ③ **SCAMPER** (7원칙) | `discovery_scamper.md` |
| 본인 강점 출발형 | ④ **이키가이** (4요소) | `discovery_ikigai.md` |

→ 선택한 1~2개 경로에서 *후보 아이템 5개* 도출

### 2. 아이템명 작성 (Naming) — 2단 흐름

**2-1단: 후보 8개 + TOP 3 추천**

필수 5가지 입력 수집:

| # | 입력 항목 | 예시 |
|---|---|---|
| 1 | 적용기술 (1~2개) | 생성형AI · 컴퓨터비전 · IoT · 빅데이터 |
| 2 | 핵심기능 (동사형 1개) | 탐지·예측·분류·추천·요약·자동화 |
| 3 | 제공혜택 (가치 1개) | 비용절감·시간단축·정확도향상·매출증대 |
| 4 | 제품/서비스 형태 | SaaS · 앱 · 웹플랫폼 · 솔루션 · API |
| 5 | 타깃/도메인 | 제조 품질팀·물류센터·병원·소상공인 |

3종 템플릿으로 후보 8개 생성:
- 기본형 3개: "OO기술이 적용된 OO기능을 제공하는 OO제품/서비스"
- 타깃 포함형 3개: "OO대상/OO분야용 OO기술 기반 OO기능의 OO서비스"
- 혜택 강조형 2개: "OO기술로 OO문제를 해결해 OO혜택을 제공하는 OO솔루션"

5축 평가 (직관성·구체성·구조충족·간결성·리스크) → **TOP 3 + 이유 1줄씩**

**2-2단: 선정가능성 강화 옵션 5개 패키지**

평가 포인트(기술성·실현가능성·성장전략·팀역량) 보강:
- 트렌드/정책·시장 부합 옵션 1~2개
- 수익모델/매출구조 옵션 2개
- PoC/실증·실행력 옵션 1개
- 차별화/방어(데이터·보안·IP) 옵션 0~1개

각 옵션 = *옵션명 + 사업계획서용 1문장 + 강화 평가축 + 증빙 2개 + 수익 연결 1줄*

→ **우선순위 TOP 2** 표시 (1~2개월 내 효과 큰 옵션)

### 3. 검증 (Validation) — 3축 메인 + 6 Hats 보강 선택

**메인 — 시장·기술·운영 3축 진단 (15문항)**

| 축 | 핵심 질문 5개 | 흔한 약점 |
|---|---|---|
| **시장** | ① 상위 3사 매출·점유율 ② 3년 성장률·5년 추정 ③ 진입 자격·인증 ④ 대체 해결 방식 가격 ⑤ 지인 5명 가격 인터뷰 | 빅테크 진입 임박 / 가격 가설 / TAM 작음 |
| **기술** | ① 핵심 기능 외주 vs 자체 ② 외주 비용·기간 ③ API 매출 대비 마진 ④ 모방 1년 내 가능성 ⑤ 5년 후 유효성 | 외주 의존 100% / 데이터 부족 / 정확도 가설 |
| **운영** | ① 대표 직접 작업 시간 ② 1인 한계 고객수 ③ 매출-비용 시차 ④ 1인 시간 묶임 ⑤ 2주 휴가 시 사업 정지 여부 | 1인 처리 한계 / 자금 회전 6M+ / 대표 시간 100% |

→ 각 축 *치명적 약점 1개* + *보완 방안 1개* 식별

**보강 (선택) — 6 Hats 멀티 페르소나 토론**
- 동업자·팀 워크숍 시 사용 (1인 단독 결정 시 스킵 가능)
- 흰·빨·검·노랑·초록·파랑 6모자 각 100단어 이상 토론
- 토론 규칙·진행 양식은 `references/validation_6hats.md` 참조

**폐기 결정 기준 — 2개 이상 해당 시 후보 폐기 권장**
- 시장 진입 자격이 *대표가 갖출 수 없는* 것 (5년 이상 자격증 등)
- 핵심 기술 외주 의존도 매출의 50%+
